# 編集ソフト連携の追加実機検証（2026-09-28）

## 対象と結論

[`NLE_EXPORT_RESEARCH.md`](/Users/mimi/Desktop/NLE_EXPORT_RESEARCH.md) の未確認項目を、macOS 上の Final Cut Pro Creator Studio 版と DaVinci Resolve 21 App Store 版で追加検証した。Premiere Pro は対象外。

**Cutpeak のタイムラインを両ソフトで再編集できる形に書き出すことは可能。** 特に FCPXML 1.10 は両ソフトでタイムラインとして読み込めたため、共通形式の有力候補になった。ただし、Resolve は今回の相対パスを自動解決せず、イージングと一部クロップの見え方も同一とはまだ言えない。完全な見た目の再現を約束する前に、下記の条件を扱う必要がある。

検証は合成素材と新規のテスト用ライブラリ／Resolve プロジェクトで行った。Cutpeak の製品コードには手を加えていない。WAV はリンクとトラック配置を確認したが、実音の聴取までは行っていない。

### クロップ換算の修正

元の調査にある FCPXML の換算例は、素材がプロジェクトと同じ 1920×1080 の場合には合う。**今回確認した左右の `trim-rect` は、素材の高さを基準に換算する必要があった。** 1280×720 素材の左 10% を切るなら 128px なので、XML には `128 / 720 × 100 = 17.7778` を書く。`left="10"` では 72px しか切れなかった。上下も同じ基準と考えられるが、実機での数値確認は残る。

### 素材パスと配布

Resolve は FCPXML と FCP7 XML のどちらでも、今回の相対パスを自動解決しなかった。これは XML と素材をアプリがアクセス可能な Movies 配下の同一フォルダに置いた場合も同じだった。一方、FCPXML の素材を `file:///Users/...` の絶対 URL で示すと自動リンクした。ZIP を受け取る利用者の展開先は書き出し時には分からないため、Web アプリから各利用者に合う絶対 URL を埋め込めない。

元の調査では、FCP7 XML 読み込み後に Resolve で素材フォルダを指定して再リンクできた。今回、Resolve のフォルダ選択画面が検証操作中に応答しなくなり、FCPXML での再リンク完了までは確認できていない。したがって「FCPXML 1 種類＋素材 ZIP」は有力だが、**Resolve で ZIP 展開後にフォルダを指定する操作が確実に完了することを、配布形態の試作で確認してから形式を一本化する**のが妥当。

### キーフレームと GIF

FCPXML の DTD には `linear`、`ease`、`easeIn`、`easeOut` が記載されている。しかし実際の Final Cut Pro は今回の位置パラメータで `interp` 属性の警告を出し、再書き出し時にその属性を落とした。したがって Cutpeak の 4 種類のイージングを XML の属性だけで忠実に渡せるとは判断できない。必要なら中間キーフレームを打って曲線を近似する試験が要る。

GIF は静止画として扱われる可能性が高いため、アニメーションを維持したい場合は動画へ変換して同梱する方針が安全。Final Cut Pro では 2 フレーム GIF の後半で色が切り替わらないことを確認した。

## 実装判断

1. 最初の実装候補は **FCPXML 1.10＋素材 ZIP**。Resolve でも FCPXML、透過 PNG、縦横別倍率、29.97fps、単独音声の取り込みを確認できたため、FCP7 XML を最初から別途生成する必然性は小さくなった。
2. Resolve 利用者向けに素材の再リンク手順を含める。まず ZIP を使った一連の操作を実機で通し、FCPXML の再リンクが成立するか確認する。成立しなければ FCP7 XML 併記を再検討する。
3. FCPXML のクロップ量は素材の寸法で換算する。Cutpeak と編集ソフトで切り抜き後の位置が違う点には、元の調査にある位置補正も適用する。
4. GIF と Cutpeak 固有の描画・効果は、必要な箇所を動画または透過 PNG に焼く。補間は忠実さの程度を明示し、中間キーフレームによる近似を別途検証する。

## 残る実機確認

- FCPXML を ZIP に同梱した状態での、Resolve の素材フォルダ再リンク完了
- Resolve での FCPXML クロップの最終的な見え方と位置補正、特に素材とプロジェクトの寸法が違う場合
- FCPXML の上下クロップでの素材寸法を使った換算
- 4 種類のイージングを中間キーフレームへ変換したときの両ソフトでの見え方
- Resolve でのアニメーション GIF の再生挙動（実装は動画化を推奨）
- WAV の実音、長めのタイムライン、異なるフレームレートを混ぜたタイムライン

検証用 XML と合成素材は `/private/tmp/nle-validation-20260928/` に置いた。Final Cut Pro の再書き出し結果は同フォルダの `FCP-crop-alpha-roundtrip.fcpxmld/Info.fcpxml`。一時フォルダ内のため永続的な成果物ではない。

## 実装後の追加確認

Cutpeak の画面から 10 秒の試験プロジェクトを書き出し、生成された ZIP を展開して DaVinci Resolve 21 の「タイムラインを読み込む」に渡した。XML は 1920×1080、30fps のタイムラインとして認識された。Resolve は相対パスの素材 11 件を最初は自動検出しなかったが、展開先の `media` フォルダを指定するとすべて読み込まれた。タイムラインには元の MP4 の映像と音声、およびアニメーション GIF から生成した赤・青の透過 PNG クリップが配置され、ビューアにも合成結果が表示された。これにより、上記の「FCPXML を ZIP に同梱した状態での Resolve の素材フォルダ再リンク完了」は確認済みになった。

ZIP 内の XML は FCPXML 1.10 DTD に適合し、ZIP の CRC と各ファイルの展開を確認した。macOS の古い `unzip` コマンドは日本語の ZIP 内パスを正しく扱えなかったが、macOS の `ditto` では正常に展開できた。README は ZIP 展開後に Final Cut Pro の「XMLを読み込む」、Resolve の「タイムラインを読み込む」と必要時の `media` フォルダ指定を案内する。

Final Cut Pro では、別の検証用 XML を読み込んだ際に `format` の名前が不正との警告が出た。製品側では未定義の `FFVideoFormat...` 名を出さず、寸法とフレーム期間だけを記述するよう修正した。修正版の最終 FCPXML については Final Cut Pro のファイル選択画面が操作中に応答しなくなり、警告の解消と生成された素材の読み込み完了は再確認できていない。完了済みと扱わず、次回の実機確認項目とする。
