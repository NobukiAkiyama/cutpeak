# 編集ソフト連携・実装計画

作成日: 2026-09-28
対象: Cutpeak → Final Cut Pro / DaVinci Resolve 21 への編集可能なタイムライン書き出し

## 目的と完成条件

Cutpeak のプロジェクトを、タイムライン情報と使用素材を含む ZIP として書き出す。利用者は ZIP を展開して Final Cut Pro または DaVinci Resolve に読み込み、カットやクリップの配置、基本的な変形、音声を引き続き編集できる。Premiere Pro は対象に含めない。

完成とする条件は次のとおり。

1. 両ソフトで同じ ZIP からタイムラインを作成でき、手順どおり素材をつなげられる。
2. 使用範囲、配置、速度、位置、縦横別倍率、回転、不透明度、音量、フェード、ディゾルブを、検証用プロジェクトで確認できる。フレーム位置・尺のずれは 1 フレーム以内とする。
3. Cutpeak 固有の描画は必要な部分だけ画像または動画に変換して見た目を保つ。変換しても編集できる範囲を、書き出し前と README に示す。
4. 必要素材の欠落、変換不能、容量不足、キャンセルを検出し、不完全な ZIP を完成品として渡さない。

根拠は [元の調査](</Users/mimi/Desktop/NLE_EXPORT_RESEARCH.md>) と [追加の実機検証](./NLE_EXPORT_VALIDATION_2026-09-28.md)。後者で FCPXML 1.10 は両ソフトに読み込めた。一方、Resolve で相対パスが自動解決されないこと、ZIP 展開後の FCPXML 素材再リンクが未完了であることを前提にする。

## 提供する形式

第一候補は **FCPXML 1.10 と使用素材をまとめた ZIP**。Resolve の素材再リンクを工程 0 で実証できた場合に、この 1 形式で進める。

```text
作品名_編集ソフト用.zip
├─ 作品名.fcpxml
├─ media/
│  ├─ 使用した元素材
│  └─ Cutpeak 固有表現から生成した素材
└─ README.txt
```

FCPXML の素材参照は `./media/...` とする。Final Cut Pro では自動リンクを確認済み。Resolve では読み込み後に `media` フォルダを指定する操作を README で案内する。**再リンクが実証できない場合は、Resolve 向け FCP7 XML を ZIP に併記する**。ZIP に展開先不明の絶対パスは書かない。

## 工程 0: 形式と変換方法の判定

製品コードを書く前に、小さな FCPXML と合成素材を ZIP にした試作品で次を実機確認する。各項目の入力ファイル、操作、FCP/Resolve の結果を検証記録に追記する。

| 確認 | 合格条件 | 不合格時の扱い |
| --- | --- | --- |
| Resolve の FCPXML 素材再リンク | ZIP を任意の場所へ展開し、案内した `media` フォルダ指定で動画・透過 PNG・WAV が全てつながる | FCP7 XML を併記する。そちらの再リンクも同じ ZIP で再確認する |
| クロップ | 異なる素材寸法で左右・上下を切り、両ソフトの表示位置と切り抜き量が Cutpeak と一致する | XML 側の位置補正を調整。再現できない条件はクリップ単位で画像化する |
| キーフレーム | 4 種類の補間、トリム、速度変更を含む位置・倍率・不透明度の結果を確認する | 属性への直接変換をやめ、中間点の追加で近似する。近似誤差を明記する |
| 動的な透過素材 | アニメーション GIF とパペット変形の画像化方法を両ソフトで再生確認する | 別の生成形式を試す。成立しない表現は明示的な書き出し不可条件にする |
| 音声と長さ | WAV の実音、元動画の音声、速度変更、29.97fps、長めの尺でずれを確認する | 音声の割り当て・時刻変換を修正して再試験する |

この工程の成果物は、採用形式、変換式、再リンク手順、画像化する条件を固定した短い互換性メモ。形式を決めるまでは UI に「両ソフト対応」を表示しない。

## 工程 1: タイムラインの変換

`Project` を直接 XML 文字列へ変える構造にはせず、まず書き出し専用の中間データを作る。中間データには、有理数 fps、トラック順、タイムライン上の開始・終了フレーム、素材内の開始時刻と速度、変形、音声、使用素材、生成素材を含める。元のプロジェクトは変更しない。

| 作業 | 要点 |
| --- | --- |
| 収集と事前確認 | 非表示トラックとミュートの扱いを `sceneAt()` / `audible()` に合わせる。ロックは編集制限なので書き出し対象から除かない。実際に使う素材だけを集め、欠落を開始前に報告する |
| 時刻変換 | `fps` の分子・分母を保持し、整数フレームから FCPXML の有理数時刻へ変換する。素材内時刻には `sourceInUs`、速度、必要なら `firstTimestampUs` を反映する |
| 通常の映像・画像・音声 | 元素材への参照、トリム、速度、トラック配置、動画と独立音声の関係を出力する。`audioDetached` で音声を二重に置かない |
| 変形 | `objectSize()` の収まり方を基準に、位置・縦横別倍率・回転・不透明度を FCPXML に変換する。キーフレームはクリップ内時刻から素材時刻への対応を踏まえて配置する |
| クロップ | 素材の縦寸法を基準に `trim-rect` の割合を求め、Cutpeak と切り抜き後の中心が一致するよう位置を補正する。上下と異寸法素材は工程 0 の結果で式を確定する |
| フェードとディゾルブ | フェードを不透明度・音量のキーフレームへ変換する。重なりのあるクリップはカット点とトランジションに組み替え、前後の素材ハンドル不足を検出する |
| 背景 | プロジェクトの背景色が見える区間を含め、プレビューと同じ合成結果になるよう背景素材またはジェネレーターを配置する |

主な追加先の案は `src/media/nle/`（中間データ、FCPXML 生成、ファイル名と素材参照）。既存の [model.ts](../src/core/model.ts)、[timeline.ts](../src/core/timeline.ts)、[renderer.ts](../src/render/renderer.ts) の値の意味を共有し、動画書き出しと別の解釈を作らない。XML は文字列連結に依存せず、属性のエスケープ、Unicode ファイル名、URL エンコード、重複名を一箇所で処理する。

## 工程 2: Cutpeak 固有表現と ZIP

- テキスト、字幕、図形は透過 PNG を生成し、位置・拡大縮小・回転・不透明度は可能な限り編集ソフト側のクリップ属性として残す。PNG の描画には既存のレンダラーを使い、文字組みの差を避ける。
- アニメーション GIF は元 GIF をそのまま渡さず、全フレームが再生される素材へ変換する。パペット変形も動く部分を画像化する。透過が必要な場合の形式と XML 上の配置は工程 0 で両ソフトの動作を確認して選ぶ。
- そのほか XML で忠実に表せない効果は、対象区間を画像化する。どのクリップが画像化され、どの操作が引き続き編集できるかを画面と README に列挙する。無言で効果を落とさない。
- `media/` 内の名前は NFC 正規化し、同名素材を一意にする。参照先は ZIP 内に存在するものだけに限定する。使っていない素材を入れない。
- ZIP 生成は Worker で進捗とキャンセルを受け付ける。大きな素材を全てメモリー上の Blob に複製しない方式を選び、可能な環境では保存先または一時領域へ順次書く。失敗・中止時には一時データを片付ける。

既存の [media-import-service.ts](../src/app/media-import-service.ts) には素材取得の仕組みがあるが、現在の `projectFiles()` は全素材を返す。編集ソフト用には使用素材のみを選ぶ取得処理を追加する。[local.ts](../src/storage/local.ts) の保存 UI は ZIP の MIME 種別と拡張子に対応させる。

## 工程 3: 書き出し画面

[ExportDialog.tsx](../src/ui/ExportDialog.tsx) の「書き出す」に **動画 / 編集ソフト用** の選択肢を追加する。編集ソフト用では対象を「Final Cut Pro・DaVinci Resolve」と表示し、ZIP の中身、素材の欠落、画像化されるクリップ、Resolve の再リンク手順を開始前に確認できるようにする。動画用のコーデック能力判定はこの経路の必須条件にしない。

進捗は「確認 → 生成素材 → XML → ZIP → 保存」に分ける。中止後の再実行、保存先を選べないブラウザでのダウンロード、同名ファイルの扱いを既存の動画書き出しと同じ操作感にする。README は採用した XML 形式に合わせて自動生成する。

## 工程 4: 自動確認と実機受け入れ

| 種類 | 確認内容 |
| --- | --- |
| 変換テスト | 30/29.97fps、トリムと速度、素材寸法の違い、縦横別倍率、クロップ位置、音量、各補間、ディゾルブの境界を固定例で検証する |
| 成果物テスト | XML が構文・DTD に適合し、XML が参照するファイルが ZIP に全て入り、展開後の名前とパスが一致することを確認する |
| ブラウザテスト | 実プロジェクトから ZIP を保存し、進捗・中止・素材欠落表示・メモリー使用を確認する。少なくとも短編と大きめの素材集合を使う |
| 実機テスト | 同じ ZIP を FCP と Resolve に読み込み、再リンク、29.97fps、映像・透過・音声・文字・図形・GIF・パペット・フェード・ディゾルブを確認する。各対象点の尺と位置を Cutpeak のプレビューと比較する |

自動テスト、型チェック、lint、ビルドに加え、実機チェックで合格してから提供する。今回の検証で未完了だった Resolve の再リンクとクロップ表示は必須確認項目とする。環境により異なるアンチエイリアスや文字レンダリングは、見た目の差を記録して許容範囲を決める。

## 実装順と完了判定

1. **互換性の判定**: 工程 0 を終え、XML 1 種類か 2 種類かを確定する。
2. **編集可能な基本タイムライン**: 工程 1 の通常素材・変形・音声までを作り、両ソフトで開く。
3. **見た目の保持**: クロップ、トランジション、画像化素材を追加し、差分を解消する。
4. **製品への接続**: ZIP、保存、書き出し画面、README、エラー・中止を実装する。
5. **受け入れ**: 工程 4 の自動確認と実機確認を通す。

途中の成果は試用版として扱い、完成条件の未達項目を明記する。特に Resolve の再リンクが成立しない状態、または GIF・パペット等が無言で欠ける状態では正式機能として出さない。

## 対象外

Premiere Pro 向けの XML・プロジェクト生成、編集ソフトから Cutpeak への逆方向読み込み、文字・図形・パペット変形を編集ソフト固有の効果として再編集する機能は今回の対象外。文字等は画像化したクリップの位置や尺を編集できる形を目指す。
