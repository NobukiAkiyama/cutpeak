# 編集履歴のコメント機能（VSCode のソース管理風）設計

## 目的

編集履歴に「この時点で何をしたか」をコメントとして残し、あとから見つけて戻れるようにする。
現状は編集 1 回ごとに履歴が 1 行増えるため、`スナップショット 15:03:16` のような名前では目印にならない。
VSCode のソース管理（メッセージ欄＋コミット＋グラフ）の形を参考に、コメント付きの記録を一覧の主役にする。

## 用語

- **編集**: 通常の操作で自動的に作られるコミット（`operations` が 1 件以上）。「履歴から復元」も編集として扱う。
- **記録**: ユーザーがコメントを付けて作るコミット。既存の `Editor.snapshot(message)` で作る空コミット
  （`snapshot: true` かつ `operations` が空、親あり）。
- **起点**: 親のないコミット（「プロジェクトを作成」）。
- **変更**: 現在地から見て、直近の記録（または起点）より新しい編集。VSCode の「変更」に相当する。

既存の `snapshot` フラグは「20 コミットごとの自動付与」「復元」でも立つため、フラグ単体では判定しない。
保存形式は変えない。既存のスナップショットはそのまま「記録」として表示される。

## データ処理: `src/core/history-log.ts`（新規）

```ts
export const isCheckpoint = (c: Commit) =>
  !c.parentIds.length || (!!c.snapshot && !c.operations.length);

export interface LogEntry {
  commit: Commit;      // 記録 または 起点
  edits: Commit[];     // この記録に含まれる編集（新しい順）
  branches: Branch[];  // head が commit または edits のいずれかにある案
}
export interface HistoryLog {
  changes: Commit[];   // まだ記録していない編集（新しい順）
  entries: LogEntry[]; // 新しい順
}
export function historyLog(r: Repository): HistoryLog;
```

- `r.head` から `parentIds[0]` を辿って起点までの 1 本の鎖を作る（訪問済みチェックで循環を防ぐ）。
- 鎖を新しい順に見て、記録／起点に出会うたびに新しい `LogEntry` を作る。
  それより古い編集は、次の記録／起点に出会うまでその `LogEntry.edits` に入る。
- 最初の記録より新しい編集は `changes` に入る。
- 表示順はタイムスタンプではなく鎖の順。他の案の履歴は表示しない（案はプルダウンで切り替える）。

## 画面: `src/ui/HistoryDialog.tsx`（作り直し）

左列（VSCode のソース管理パネル相当）

1. **案の切り替え**: 今と同じ `Choice` のプルダウン。カメラの「スナップショット」ボタンは削除する。
2. **別案フォーム**: 今と同じ（名前入力＋「別案を作る」）。
3. **変更 (N)**: 折りたためる見出し（初期状態は開く）。`changes` を「メッセージ・時刻」で並べる。
   0 件なら「前回の記録から変更はありません」と表示する。行を押すと右列に詳細が出る。
   現在地の行には「現在地」と表示する。
4. **メッセージ欄**: `textarea`。
   - プレースホルダー: `メッセージ (⌘Enter で "<案の名前>" に記録)`。Mac 以外は `Ctrl+Enter`。
   - 入力に合わせて高さが伸びる（上限あり、超えたらスクロール）。
   - ⌘Enter / Ctrl+Enter で記録する。日本語変換中（`isComposing`）は何もしない。
   - 入力中の文章はダイアログを閉じても残す（モジュール内の変数に保持。ページを再読み込みしたら消える）。
5. **記録ボタン**: 全幅。メッセージを `trim` して空なら押せない。
   押すと `api.snapshot(message)` を呼び、欄を空にし、選択を現在地に戻す。
   変更が 0 件でも記録できる（復元直後や別案を作った直後に目印を付けたい場合があるため）。
6. **グラフ**: `entries` を縦線でつないで並べる。
   - 行: 記録の 1 行目（長ければ省略）、時刻、案のバッジ（`main` のような丸いラベル）、現在地なら「現在地」、
     含まれる編集があれば「N 件の編集」。
   - 行を押すと選択し、含まれる編集をその下に字下げして開閉する（VSCode のグラフでコミットを開く動き）。
   - 開いた編集の行を押すと、その編集を選択する。

右列（今の「変更内容」パネル）

- 選択中のコミットの詳細を出す。初期選択は現在地。
- 記録: コメント全文（改行を保持）、日時、「N 件の編集を含みます」。
- 起点: 今と同じ「この時点のプロジェクト全体を保存しています。」
- 編集: 今と同じ操作の一覧（タイムコード・対象・説明）。
- 「この時点へ復元」ボタンと注記は今と同じ。現在地では押せない。

スマホ幅では今と同じく 1 列に積む。見た目は既存の `commit-*` クラスとテーマ（`occamus.css`）に合わせる。

## 既存コードへの影響

- `Editor` と保存形式は変更しない。`api.snapshot(message)` をそのまま使う。
- グローバルのキーボードショートカットは `textarea` と `[role=dialog]` 内を無視するので干渉しない。

## テスト

- `tests/history-log.test.ts`（新規）
  - 記録がない場合、起点だけが `entries` に入り、編集はすべて `changes` に入る。
  - 記録の前後の編集が、正しく `changes` と `entries[i].edits` に振り分けられる。
  - 「20 件ごとの自動 snapshot」や「履歴から復元」は記録として扱われない。
  - 別案に切り替えると、その案の鎖だけが表示される。案のバッジが正しい記録に付く。
  - `undo` 後は現在地より先の編集が表示されない。
- `tests/browser/editor-workflow.spec.ts`
  - 履歴ダイアログでメッセージを入力し、⌘Enter（Ctrl+Enter）で記録するとグラフに表示される。
  - 空のときは記録ボタンが押せない。

## 今回やらないこと

- 記録済みコメントの後編集（履歴の書き換えになり、ドライブ同期が複雑になるため）。
- 複数の案を同時に描くレーン付きグラフ。
- 記録ボタンのプルダウン（「記録して別案を作る」など）。
